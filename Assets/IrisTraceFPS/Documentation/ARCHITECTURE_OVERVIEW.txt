IRISTRACE FPS — ARCHITECTURE OVERVIEW

RUNTIME
- Core: contracts shared across gameplay modules.
- Input: adapter around Unity Input System.
- Characters: movement, camera and player health.
- Weapons: firing, ammunition and reload behavior.
- Abilities: independently assigned character skills.
- Enemies: target health and basic AI behavior.
- UI: runtime HUD for health, ammo and abilities.

EDITOR
- Windows: generator and content libraries.
- Generators: build prefab and test scene objects.
- Validation: detect common configuration issues.
- Release Audit: check key folders, assembly definitions and Input System declaration.

DATA AND OUTPUT
- Reusable definitions are stored as Unity assets/configurations.
- Generated prefabs and configurations are kept separately under Assets/IrisTraceFPS_Generated/.
- IDs identify saved definitions; display names may change.

DEPENDENCY RULES
- Runtime code must not depend on Editor code.
- Weapons should target damage/health contracts, not concrete character classes.
- Ability activation should use ability contracts, not hard-coded hero types.
- Input details should stay behind the input adapter.

This overview describes intended module boundaries. Verify actual behavior and dependencies in the current project before release.
